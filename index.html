The 20-minute path

Do these in order. The order matters: a failed data URL or a missing bridge file is a page error in the render check, and the twin will not publish even if the review passes.

1

Pick one place and one live source

Not a category. One place with coordinates, one instrument or process, one URL that returns JSON with CORS. Write down the units, datum, cadence and whether it is observed, recorded or simulated. If the source has no CORS, stop here — the sandbox cannot proxy it.

2

Copy the starter

Take starter/app.json and starter/entry.js. Change the coordinate, the source URL, the panel title and the model. Keep the shape: build the scene first, fetch second, panel last.

3

Run it locally over HTTPS

?app=http://127.0.0.1:PORT/app.json works in principle, but a page served over HTTPS may refuse a module import over HTTP. The reliable local loop is a tunnel: cloudflared tunnel --url http://127.0.0.1:PORT, then open https://maps.ce-net.com/?app=https://<tunnel>/app.json. Serve with Access-Control-Allow-Origin: *.

4

Dry-run the review

Call twin_submit with dry: true. It returns a score, reasons, fixes and checks (static, owner, ai, render). Iterate until the AI score is ≥ 70 and the render check has no page errors. A dry run publishes nothing.

5

Publish the bridge, then the twin

The manifest's data URLs are fetched by the live page. If the Trana bridge JSON does not exist yet, that 404 is counted as a render error. Publish the static bridge first (or remove the URL until it is live), then submit.

6

Attach the thread, trust and accuracy

Open a Trana thread for the twin, put its id in the bridge JSON, republish the bridge, and post the holdout error and the source. The twin panel now has a social and trust layer, not just a model.

The contract

A third-party twin is two files: app.json (a manifest) and entry.js (an ES module exporting start(ctx)). The manifest is fetched first; the module is imported into a sandboxed iframe with no same-origin access. The host checks every call against the manifest's needs.

{
  "id": "lowercase-id",
  "title": "3–60 characters",
  "what": "20–240 chars: what it shows and where the data comes from",
  "kind": "twin",
  "needs": ["local", "box", "orbit", "panel", "steps", "data"],
  "data": ["https://api.example.org/observed.json"],
  "models": [],
  "entry": "entry.js"
}
fieldrule
id3–40 of a-z0-9-; the id stays yours; a new submission with the same id updates it.
whatSay what it shows and where the numbers come from. “Live” is only allowed if a live URL is in data.
kindtwin for a real place/instrument/process; scene for a lesson or a visual with no operational claim; layer for data on the globe; lesson for a guided teaching piece.
needsEvery non-free ctx op you call. set, remove, data, every, on and log are allowed without listing. Declaring fewer than you use gets the call refused with the missing op.
dataExact HTTPS URLs. Only these can be fetched by ctx.data. A failed fetch is a page error in the render check, so publish the file before the twin.
entryThe module file. For twin_submit, send the source as entry_js (200 B–256 KB) or a URL as entry_url; the service writes the manifest.

The ctx reference

The sandbox exposes a small, generic surface. There is no DOM, no fetch except ctx.data, no storage, no eval, and no three.js. Every object you add is removed when the app unloads.

opwhat it does / what to know
ctx.local(lat,lon)A local frame in metres: x east, y up, z south. Await its handle; pass it as frame to every box/model.
ctx.box({frame,size,at,color,emissive,heading})The building block. at is the base, size is metres. Returns a handle for ctx.set. Use boxes for buildings, water, piers, chart bars, even trees.
ctx.model(lat,lon,url,{...})A glTF/GLB in metres. URL must be in models. fit, near (level of detail), frame.
ctx.points(rows,{lift})One draw call for many globe points: [lat,lon,size,"#rrggbb"]. Not local metres.
ctx.arc(a,b,color,opacity)A great-circle arc between two [lat,lon] places. Not for local links.
ctx.ring(lat,lon,size,color,period)A pulsing ring flat on the ground. size is in globe radii, not metres.
ctx.orbit(lat,lon,dist,{heading,tilt,min})Close 3D: orbit a ground target at dist metres. min is the closest the viewer may zoom.
ctx.fly(lat,lon,alt)Fly the camera on the globe; alt is in globe radii (0.18 ≈ 1,100 km).
ctx.base(name,on)Hide a base layer: density, lanes, links, twins.
ctx.panel({title,sub,rows,list,actions,source})The panel. rows is [label,value]; actions are buttons with onClick; list is clickable sources. There is no body in the sandbox — build charts from boxes or rows.
ctx.steps([{title,text,at,do,view}])A guided tour. at is [lat,lon,metres]; do calls a handler registered with ctx.on(name, fn).
ctx.every(fn)fn(dtSeconds, nowMs) every frame, capped by the host. Keep work per frame small.
ctx.set(handle,{at,heading,scale,visible,color})Move, rotate, scale or recolour an object. at is the centre, not the base.
ctx.data(url)Fetch JSON from a URL listed in data. CORS is required. The only network call the app gets.
ctx.log(msg)Console only; do not use it as a user-facing error path.
No labels, no lines, no charts in the sandbox. There is no ctx.label, ctx.line or ctx.chart. Build a legend/axis from boxes and put the numbers in panel.rows. This is the main reason a twin looks like a toy: the author did not know the chart had to be geometry.

Live data + a model people can check

The pattern that survives review is boring and explicit. It has four parts:

  1. Reality — an observed feed with units, datum, cadence and an age. Show the age; do not call a 2-hour-old reading “live”.
  2. Model — one named model. A harmonic tide, a power curve, a queue, a rating curve. State its inputs and its assumptions.
  3. Holdout error — fit on the older part of the window, score on the last 12 h (or 20%). Show the error next to the baseline model. If your model is worse, say so and let the viewer turn it off.
  4. Provenance — the URL, the station id, the licence/credit, the fetch time, and whether the value is observed, recorded or simulated.
const obs = await ctx.data(OBS_URL);      // reality
const tide = await ctx.data(PRED_URL);    // external model
// fit surge on the older 36 h, score on the last 12 h
const model = fitSurge(obs, tide, weather);
// panel rows: observed, tide, twin, surge, holdout MAE, tide-only MAE, age, source
ctx.panel({ title: "…", rows, source: "station id · units · datum · credit" });

Two rules keep this honest:

  • Never mix observed and simulated in one number without a label. “Twin 1.33 m” must say tide + simulated surge; the observed is a separate row.
  • Make the model falsifiable. A holdout error, a baseline, and an on/off switch let a reviewer disagree with you. A model with no error is a claim with no test.

What the review checks

The AI review scores five things out of 100; 70 passes. The render check is separate and must be clean: no page errors, not blank. The refusal lists its reasons and fixes — read them as a design review, not a rejection.

axiswhat earns pointswhat loses them
PurposeA real place, instrument or process; a viewer learns something specific.A test scene, a placeholder, “Location: a test point”, geometry with no subject.
HonestyObserved vs simulated is labelled; units and datum; source; limitations; holdout error.“Live” with no live URL; a model presented as measurement; invented facts.
CraftUses only declared needs; readable code; a scene that explains the subject; a guided tour.Undeclared ops; a panel of filler; a single unlabelled box.
SafetyNo network beyond data, no tracking, no impersonation, no eval.External calls, hidden payloads, fake authority.
SlopSpecific nouns, real numbers, a reason to exist.Generic “digital twin” language, made-up place names, decorative noise.

Common refusals we hit, and the exact fix

render FAILED net::ERR_FAILED https://…/bridge.json — the manifest lists a data URL that does not exist. Publish the file, or remove the URL until it is live. The AI score can be 81 and the twin still will not publish.

ai score 18 of 100 — a test scene with two boxes. The fix was not “more boxes”; it was a real subject, a named source, a holdout error, and a reason to look.

static no op box not in needs — declare every op. needs is a permission list, not documentation.

auth needs a signed-in connection — twin_submit works at /mcp/account with an account session, not an agent key at /mcp. A dry run is free; do it before you write the long description.

Trana bridge: make the twin social and checkable

A published twin has a score, but no thread, no reviewer and no trust. The bridge is a small JSON file the twin fetches, so the panel can show the social layer without giving the sandbox a network. Publish it on a static site, keep it fresh, and let the twin say when it is stale.

{
  "schema": "twinton.trana/1",
  "twin": "battery-tide-twin",
  "thread": "t-…",                       // Trana thread, or null
  "thread_url": "https://trana.app/…",
  "proposal": "v-…",                     // optional decision
  "trust": { "account": "acct:…", "score": 0.0, "verified": 0, "reviews": 0 },
  "mesh": { "twins": 1, "sources": 1, "threads": 1, "updated": 1793060000 },
  "sources": [{
    "id": "noaa-8518750", "url": "https://api.tidesandcurrents.noaa.gov/…",
    "kind": "observed", "cadence_s": 360, "units": "m MLLW",
    "credit": "NOAA CO-OPS, station 8518750, preliminary"
  }],
  "streams": [{ "id": "trana-thread", "kind": "social", "url": "https://trana.app/…" }],
  "updated": 1793060000
}

The twin treats the bridge as an optional dependency: if it is missing, the panel says “bridge offline” and the twin still renders. The bridge is the place where a reviewer can see who checked the twin, where the discussion is, and which data streams feed it — the social network around the model, not a second copy of it.

The mesh rule: the twin id, the thread id, the source ids and the trust subject must be the same strings in the model, the bridge and the thread. A bridge that points at a thread about a different twin is worse than no bridge.

Live example: the-battery-tide.json points at NOAA 8518750, Trana thread t-5a2f306903e5, proposal v-6adfef7b7b31, and the twin id battery-tide-twin. The thread is the finding; the bridge is the pointer.

Gotchas, measured

  • Auth split. An account Bearer token works at /mcp for reads, but twin_submit checks the account connection at /mcp/account. Cloudflare may block a non-browser client there; a browser User-Agent plus the token works. An agent key alone is refused for publishing.
  • Failed fetches fail the render. The render check opens the live page; a 404 in data is a page error. This is the difference between a 81/100 AI pass and a publish.
  • No text in the sandbox. Labels, axes and legends are boxes or panel rows. Plan for it before you model 300 objects.
  • Thread caps. thread_post bodies are cut at 1,000 bytes, silently; split into numbered continuations and read back. There is no idempotency, so check before retrying.
  • No CORS, no data. The sandbox has one network op and no proxy. A source that does not send Access-Control-Allow-Origin cannot be used, no matter how good it is.
  • Static bridge can stale. Show updated and say “stale” after 24 h. A trust number that is a week old is a claim about last week.
